- 因子归因能产生非中性信号（72%的推荐有sub_score>60的因子）

- 反馈循环理论上能修正方向，但因门槛过高+数据稀疏无法有效工作

### P0. 因子方向验证（预计0.5天）

**目标**：确认每个因子的实际预测方向，判断是否需要符号反转。

**操作步骤**：

1. **评分符号取反检查**（1小时内完成）：
   - 取一只历史数据完整的股票（如贵州茅台 sh600519），手工构造一个"明显看多"的因子输入：
     - MACD金叉、均线多头排列、放量上涨、突破20日新高
   - 调用 `scorer._score_trend(factors)`，验证输出是加分还是减分
   - 遍历 `_score_strategy`、`_score_chip`、`_score_oversold_rebound` 等核心函数
   - **如果本应加分的条件导致减分，或反之，说明评分函数内有符号取反bug**
   - 修复后，直接回测验证T+1胜率是否有改善

2. **直接查询已有归因数据**（建议使用近60天数据，避免旧数据干扰）：
    ```python
    # 从 factor_attribution 表聚合，建议限定近60天
    SELECT factor_name,
           SUM(CASE WHEN result='correct' THEN 1 ELSE 0 END) as hits,
           SUM(CASE WHEN result='wrong' THEN 1 ELSE 0 END) as fails,
           COUNT(*) as total
    FROM factor_attribution
    WHERE date >= date('now', '-60 days')
    GROUP BY factor_name
    ```
   对IC为负的因子（oversold_rebound=-0.10, trend=-0.05, ashare_specific=-0.03）：
   - 从 `factor_attribution` 表分别统计命中/失败数
   - 如果失败数>命中数且准确率<40%，标记该因子需反转

3. 输出**因子方向报告**：
   ```
   reports/factor_direction_report.md
   ```

**验收标准**：
- 输出因子方向报告，每个因子明确标注"正向有效/负向有效/无效"
- 需要反转的因子列表
- 不需要反转的因子列表

### P1. 基线对比：随机选股 vs 均匀权重 vs 当前权重（预计1天）

**目标**：建立纯随机选股的基线，判断当前因子组合是否比"不做任何选股"更差。

**背景**：均匀权重不等于不选股——如果所有因子都反向，均匀权重仍然选到差股票。需要同时跑纯随机基线才能分离"因子方向问题"和"权重分配问题"。

**操作步骤**：

1. **纯随机基线**：
   - 复制 `run_backtest.py` 为 `run_backtest_random.py`
   - 修改选股逻辑：每次从**与当前系统相同的候选池**（同一日期的同一批有数据、有评分的股票）中**随机选10只**，而非按评分排序选Top10
   - 这样做确保候选池一致性——区别仅在于"选股策略"而非"候选范围"
   - 运行回测，记录T+1/T+3/T+5胜率

2. **均匀权重基线**：
    - 备份当前config.yaml
    - 设置所有24维权重为均匀分布（1/24 ≈ 0.042）
   - 运行回测run_backtest.py（使用原始排序逻辑，仅改权重）

3. **对比三组结果**：

   | 方法 | T+1胜率 | T+3胜率 | T+5胜率 | 含义 |
   |------|---------|---------|---------|------|
   | 纯随机 | ~50% | ~50% | ~50% | 不做选股的基准 |
   | 均匀权重 | ? | ? | ? | 因子系统本身的价值（无权重优化） |
   | 当前权重 | 40.6% | 43.0% | 38.9% | 现状 |

4. **决策树**：

   ```
   当前权重 vs 纯随机？
   ├─ 当前 > 随机 → 因子系统有正向价值，可继续优化
   │   └─ 当前权重 vs 均匀权重？
   │       ├─ 当前 > 均匀 → 权重分配有效，继续优化权重
   │       └─ 当前 ≤ 均匀 → 权重分配失效，重置为均匀权重再迭代
   └─ 当前 ≤ 随机 → 因子系统整体有害
       └─ 均匀权重 vs 随机？
           ├─ 均匀 > 随机 → 因子有信号，权重是问题
           └─ 均匀 ≤ 随机 → 因子系统根本性失效，需重建
   ```

**验收标准**：
- 产出三组对比回测数据
- 根据决策树定位当前系统的瓶颈（因子vs权重）

**回滚**：恢复config.yaml备份即可。

### P3. 降低反馈循环调权门槛 + 引入行业级归因聚合（预计1.5天）

**目标**：让反馈循环能更灵敏地响应因子失效信号，并解决个股归因数据稀疏（5000+股每天仅10条推荐）导致个股调权无法生效的问题。

**修改参数**（`src/engine/feedback_loop.py`）：

| 参数名 | 当前值 | 目标值 | 理由 |
|--------|--------|--------|------|
| `MIN_ATTRIBUTION_SAMPLES` | 5 | 3 | 衰减加权下累加慢，降门槛加速 |
| `MAX_WEIGHT_CHANGE` | 0.02 | 0.05 | 允许单次更大调整 |
| `FAILURE_WEIGHT_PENALTY` | 0.3 | 0.5 | 因子失效时惩罚更重 |

**修改参数**（`src/engine/stock_weight_manager.py`）：

| 参数名 | 当前值 | 目标值 | 理由 |
|--------|--------|--------|------|
| `MIN_SAMPLES` | 1 | 1(保留) | 已降低过，保持 |
| `MAX_WEIGHT_CHANGE` | 0.02 | 0.05 | 与全局调权对齐 |

**解决个股归因稀疏：引入行业级归因聚合**

根因：5000+只股票每天仅推荐10只，单只股票平均每500天才被推荐一次，`stock_weight_manager`的个股调权机制在这个数据密度下几乎永远无法生效。

方案：在`stock_weight_manager.py`中增加行业级归因聚合层。

```python
class StockWeightManager:
    def _get_sector_weights(self, code: str) -> Dict[str, float]:
        # 1. 获取该股票的行业
        # 2. 查询同行业所有股票的历史归因数据
        # 3. 聚合为行业级因子权重
        # 4. 返回该行业的权重配置
        pass

    def get_weights(self, code: str) -> Dict[str, float]:
        per_stock = self._get_stock_weights(code)  # 原有逻辑
        if per_stock is not None:
            return per_stock                       # 个股有足够数据时用个股权重
        sector = self._get_sector_weights(code)    # 不足时fallback到行业权重
        if sector is not None:
            return sector
        return dict(self.global_weights)            # 行业也不足时回退全局
```

实施步骤：
1. 在`stock_weight_manager.py`中增加行业映射表（复用`MarketDataFetcher.get_industry_map`）
2. 修改`adjust_weights_for_codes`：写入个股归因→同时写入行业聚簇
3. 修改`get_weights`：个股不足时fallback到行业权重

**验收标准**：
- 修改后运行`run_feedback_training.py --smoke-test`，个股权重变化数>0
- 全局权重调整频率从每5-10天一次提升到每2-3天一次
- 个股权重能通过行业fallback获得有效值（即使该股从未被推荐过）

**风险**：门槛过低可能导致权重在小样本下过拟合。需要监控权重变化是否稳定。

### P4. 评分区分度监控（预计0.5天）

**目标**：量化监控每日评分分布，判断因子组合是否有区分能力。

**实现**：在`run_feedback_training.py`的每日循环中增加以下输出：

```python
def monitor_score_distribution(candidates):
    scores = [c["score"] for c in candidates]
    scores.sort(reverse=True)
    top1 = scores[0]
    median = scores[len(scores)//2]
    bottom10 = scores[len(scores)//10]
    std = np.std(scores)
    return {
        "top1": top1, "median": median,
        "gap_top_median": top1 - median,
        "gap_top_bottom10": top1 - bottom10,
        "std": std,
    }
```

监控指标：

| 指标 | 健康值 | 预警值 |
|------|--------|--------|
| Top1 - 中位数 | >20分 | <10分 |
| 评分标准差 | >8分 | <4分 |
| Top10均分 - 中位数 | >10分 | <5分(当前状态) |

**输出**：追加到`reports/score_distribution.log`，格式：

```
2026-07-27: candidates=5076, top1=72.3, median=50.0, gap=22.3, std=8.5, status=HEALTHY
2026-07-28: candidates=5076, top1=68.1, median=50.0, gap=18.1, std=7.2, status=WARN
```

**验收标准**：
- 持续监控7天，评分区分度无异常下降
- 预警触发时自动提醒

```
("strategy", "trend")
```

### P6. 因子方向修正（预计5-10天）

**目标**：在P0验证的基础上，针对方向有问题的因子修正其打分逻辑。

**现有问题**：
- `trend`、`strategy`等因子是后视镜——衡量"已经涨了多少"而非"将要涨多少"
- 如果市场呈现均值回归特性，后视镜因子会反向预测
- 但具体是均值回归还是动量持续，需要P0的实际数据来判断，而非预设假设

**操作步骤（分阶段执行）**：

#### 阶段A：快速取反（0.5天，低风险验证）

前置条件：P0确认某个因子方向确实反向，且P1基线已建立（用于对比取反效果）。

在确认P0中某个因子方向确实反向后，先做最简单的修正——取反现有打分逻辑：

```python
# 当前：加分当买点
def _score_trend(self, f):
    if f.get("macd_golden_cross") == 1:
        score += 15   # MACD金叉 → 加分
# === 改为 ===
def _score_trend(self, f):
    if f.get("macd_golden_cross") == 1:
        score -= 15   # MACD金叉 → 减分（因反向预测）
```

取反后立即回测验证T+1胜率是否有改善。如果取反后组合T+1胜率相比P1基线提升≥3pp，说明问题确实是方向反了，进入P6B系统性修正；如果提升<3pp，说明因子本身无效或方向不是根因，取消P6B。

#### 阶段B：系统性修正（4-9天，仅在阶段A确认有效后执行）

1. **增加动量衰减指标**（`src/factors/technical.py`）：
   ```python
   # 动量衰减 = 今日涨幅 - N日均涨幅
   # 正值表示加速上涨(可能见顶)，负值表示减速(可能见底)
   def momentum_decay(close, period=5):
       recent_return = close[-1] / close[-period-1] - 1
       historical_return = close[-period-1] / close[-2*period-1] - 1
       return recent_return - historical_return
   ```

2. **均值回归因子权重提升**（`src/engine/scorer.py`）：
   - 当前`_score_ashare_specific`中均值回归信号权重为20分加减
   - 建议将均值回归层移出`ashare_specific`，独立为因子或提升权重
   - 判断依据：如果P0/P1确认市场呈均值回归特性，则执行；否则跳过

3. **因子方向验证**（重复P0）：
   - 修改因子后重新验证方向
   - 确保修改后的因子方向趋近正向（sub_score>60 → T+3收益为正）

**验收标准**：
- P0中的因子方向报告中，需反转的因子数量减少≥50%
- 不存在IC绝对值>0.05但归因准确率<45%的因子（无论IC正负；含deep_research IC=+0.0665、oversold_rebound IC=-0.1018等）
- 归因准确率相比P0基线提升≥10个百分点（以P0重新计算的归因准确率为准）

**风险**：因子重设计最容易过拟合历史。必须在互斥的时间段上验证（上半年做训练、7月做验证）。阶段A的快速取反应在1天内完成，避免在无效方向上花费过多时间。符号反转后需在P1基线的交叉验证集上验证，确保改善不是过拟合的结果。

### P7. 恢复ML模型（预计2天，分两步执行）

#### P7a. 影子模式（0.5天，依赖P2）

**目标**：在正式启用ML之前，先收集ML预测与现有评分的对比数据，验证ML是否有正向价值。影子模式下ML**不参与推荐决策**，不修改权重。

**前置条件**：
- P2（代码路径一致性已修复）——确保ML训练数据来源可靠

**操作步骤**：

1. 在`run_feedback_training.py`的每日循环中增加影子ML路径（保留`skip_ml=True`）：
    ```python

    fb_result = fb.run_all(today=today, skip_ml=True)
    ```

    ```python

        """
        影子ML训练：从factor_snapshots加载全市场数据，训练独立模型。
        与主模型完全隔离，不共享权重、不写入weight_history。
        """
         # 1. 加载factor_snapshots中近90天数据（1502只股票）
         # 注：ML训练用90天（更多样本=更好模型），P0查询用60天（避免旧数据干扰归因分析），目的不同故窗口不同
        snapshots = load_factor_snapshots(today, lookback_days=90)
        # 2. 构建特征：22维sub_score + 元数据（市值、行业等）
        X = build_features_from_snapshots(snapshots)
        # 3. 构建标签：T+3收益率 > 1% 为正例
        y = build_labels_from_snapshots(snapshots, horizon=3, threshold=0.01)
        # 4. 训练LightGBM（与主模型相同架构，独立超参）
        model = lgb.LGBMClassifier(n_estimators=100, max_depth=5)
        model.fit(X, y)
        return ShadowMLModel(model, today)
    ```

**验收标准**：
- ML单独回测T+3胜率≥50%（滚动前向验证：每日用近90天数据训练→预测当日→T+3日验证，每交易日产生一个out-of-sample样本，7天运行累积≥5个有效样本）
- ML评分与现有评分无完全重合（重合度<80%），说明ML带来增量信息

### 5.4 终止决策标准

在关键阶段设置决策点，每个决策点基于数据决定"继续/调整方向/停止"。

```
  决策点1: P0/P1完成后                决策点2: P0评分函数符号检查
  ┌──────────────────────┐           ┌──────────────────────┐
  │ 当前权重 vs 纯随机基线 │           │ 有符号取反bug?        │
  └──────────┬───────────┘           └──────────┬───────────┘
             │                                   │
   ┌─────────┼─────────┐                 ┌───────┴───────┐
   ▼         ▼         ▼                 ▼               ▼
当前>随机  当前≈随机  当前<随机          有bug            无bug
   │         │         │                 │               │
   ▼         ▼         ▼                 ▼               ▼
 继续P2-P7  暂停评估   回退方案        修复后重新跑P1   继续P3-P7
    │     因子值得?      │            重新对比基线①
    │    ┌───┴───┐       ▼
    │   是      否    停止选股
    │    │       │    仅用均匀权重
    │    ▼       ▼    或随机
    │  继续   停止项目
    │  但调低  转为"纯数据
    │  预期    监控"模式
```

> ① 修复→重新跑P1的基线**仅用于诊断参考**：证明该bug确实是性能瓶颈，P6A方向修正有依据。建立基线后立即回退修复，代码保留bug状态直到P6A处理。决策点1（当前vs随机）使用回退后的当前代码对比。

**具体决策点**：

| 决策点 | 条件 | 动作 |
|--------|------|------|
| P1结束后 | 当前权重 ≤ 纯随机 - 3pp（含噪声容差） | 暂停，评估因子系统是否值得继续投入 |
| P1结束后 | 当前权重 ≈ 纯随机（差异<3pp视为≈）且均匀权重 ≈ 纯随机 | 因子系统根本性失效，转为数据监控模式 |
| P1结束后 | 当前权重 ≈ 纯随机（差异<3pp视为≈）且均匀权重 > 纯随机 | 因子有信号但权重分配失效，重置为均匀权重继续优化 |
| P1结束后 | 当前权重 > 纯随机 且 当前权重 ≤ 均匀权重 | 权重分配失效，重置为均匀权重继续优化 |
| P0第1步 | 评分函数有符号取反bug | 立即修复，重新跑P1基线 |
| P6A结束后 | 取反后T+1胜率提升<3pp | 取消P6B（系统性修正），因子方向问题不是根因 |
| P7A运行7天后 | ML回测T+3胜率<50% | 取消P7B，ML不纳入推荐决策 |
| 任意阶段 | 连续3次回测结果无改善（每次间隔≥3个交易日，改善幅度<0.5pp视为无改善） | 暂停该阶段，重新评估方案假设 |
